Overview: Why We Use GitHub Codespaces

To build websites that use PHP and databases, you need a web server running on your computer or in the cloud. In a traditional class, students install programs like MAMP or XAMPP — but those cannot be installed on Chromebooks, school-managed tablets, or locked-down laptops.

Instead, we use GitHub Codespaces, which gives you a complete, professional web server running entirely in your browser. There is nothing to download or install.

  • Works on any device: Chromebook, iPad, Android tablet, laptop, desktop — it doesn't matter.
  • Real-world setup: You get Apache, PHP 8.3, and MySQL 8.0 — the same tools used on real web servers.
  • Saves automatically: Your work is stored in GitHub, so you can pick up where you left off from any device.
  • No admin password needed: Nothing is installed on your device.

Part 2: Explore Your Environment

Now that your Codespace is open, take a look around.

  1. Look at the File Explorer on the left side. You will see a set of folders. Here is what each one is for:
    Folder / File What It Is
    public/ Your website files go here. This is what Apache serves to the browser.
    public/examples/ Working PHP and HTML examples included with the course.
    database/ Database configuration and sample data.
    assignments/ Starter files for your assignments.
    lessons/ Course lesson materials.
  2. Open the integrated terminal.
    The terminal lets you type commands directly to the server. To open it, go to the top menu and click Terminal → New Terminal. A panel will appear at the bottom of the screen.
    📸 [Screenshot: Terminal panel open at the bottom of VS Code]
  3. Verify your PHP version. In the terminal, type the following command and press Enter: 
    php -v
    You should see output similar to: 
    PHP 8.3.x (cli) ...
    The version number should start with 8.3.
    📸 [Screenshot: Terminal showing output of "php -v" with PHP 8.3.x]
  4. Check that Apache is running. In the same terminal, type: 
    pgrep -a apache2
    If Apache is running, you will see one or more lines of output with process IDs and the word apache2. If nothing appears, try reloading your Codespace (see Troubleshooting at the end of this document).

  2. Find port 80 in the list. You will see a row labeled "Web Application (HTTP)" with a port number of 80.
  3. Click the globe icon (🌐) next to port 80, or hover over the row and click "Open in Browser". A new browser tab will open showing your course homepage.
    📸 [Screenshot: Browser showing the CIS 047 homepage served from the Codespace]
  4. Notice the URL. It will look something like: 
    https://your-codespace-name.preview.app.github.dev
    This is your personal, private web address for this Codespace. Keep this tab open — you will use it in the next part.
✅ You are now looking at a website running on YOUR web server!

Apache is running inside your Codespace, PHP is interpreting the files, and the page is being delivered to your browser — exactly like a real web hosting environment.

Part 5: Make and Save a Change

Now you will edit a file, preview your change, and save your work to GitHub. This is the same workflow you will use for every assignment in this course.

  1. Open public/index.php in the editor.
    In the File Explorer on the left, click public, then click index.php. The file will open in the editor.
  2. Find the footer line. Scroll to the bottom of the file and look for this line: 
    <p>&copy; 2024 CIS 047 Course. All rights reserved.</p>
  3. Change the year to the current year. Click on 2024 and type the current year instead.
  4. Refresh your browser preview. In the browser tab showing your site (.../index.php or just the homepage), refresh the page. You should see the updated year in the footer.
    💡 Auto-save is on!

    Your files save automatically in VS Code. You do not need to press Ctrl+S (though you can if you want). Changes appear in the browser as soon as you refresh.

  5. Commit your change to GitHub. Now you need to save your work to GitHub so your instructor can see it. Follow these steps:
    1. Click the Source Control icon in the left sidebar — it looks like a branching path (🔀) and may show a small blue number badge if there are unsaved changes.
    2. You will see your changed file listed under "Changes". Click the "+" icon next to the file name to stage it (this means you are telling Git you want to save this file).
    3. In the text box at the top that says "Message", type a short description of what you changed. For example: 
      Update footer year to current year
    4. Click the blue Commit button (checkmark ✓), or press Ctrl+Enter (Windows) / Cmd+Enter (Mac/iPad). On a tablet without a keyboard, just click the ✓ button.
    5. After committing, click the blue Sync Changes button that appears. This pushes your commit up to GitHub.
    📸 [Screenshot: Source Control panel showing a staged change and a commit message typed in]
  6. Verify on GitHub. Open a new browser tab and go to your repository on GitHub (https://github.com/YOUR-USERNAME/cis047-course-template). Look at the commit history — you should see your new commit at the top with the message you wrote.
    📸 [Screenshot: GitHub repository showing the most recent commit with your message]

Troubleshooting

The Codespace won't load or takes a very long time:

  • Wait 2–3 minutes and try refreshing your browser tab. The first build can take a while.
  • Try a different browser (Chrome is recommended for Codespaces).
  • Disable any browser extensions that block scripts or ads — they can sometimes interfere with Codespaces. Try opening in a private/incognito window.

Database connection error on database-connect.php:

  • MySQL sometimes takes 30–60 seconds to fully start up on first launch. Wait one minute and refresh the page.
  • If it still fails, try running this in the terminal: mysqladmin ping -h db -u root -proot. If you see mysqld is alive, the database is up and the issue is elsewhere. Reach out for help.

Can't find the Ports panel or port 80:

  • Look at the very bottom of the VS Code window for a row of tabs labeled Terminal, Output, Problems, Ports. Click Ports.
  • If port 80 is not listed, try opening the Command Palette (Ctrl+Shift+P / Cmd+Shift+P / tap ... on tablet) and type "Forward a Port", then enter 80.

Need to rebuild the container (last resort):

  • Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P / tap ...), type "Codespaces: Rebuild Container", and press Enter. This takes about 2 minutes and fixes most setup problems.

PHP version shows something other than 8.3:

  • This should not happen with the course template, but if it does, try rebuilding the container (see above).
